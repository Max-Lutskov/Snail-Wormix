# Руйнівна земля — дизайн

Статус: погоджено в обговоренні 2026-11-02. MVP-пункт 2 (+ частина пункту 3: вода).

## Навіщо і що важливо

Земля — поле бою, яке вибухи перетворюють на кратери, печери й обриви. Відчуття — як у
Castle Buster: кожен постріл помітно змінює карту. Але руйнуємо саму землю, без будівель.

Обов'язково:

- **Детермінізм.** Та сама послідовність вибухів дає ту саму землю до пікселя на будь-якому
  клієнті, сервері та в реплеї (кліпи для TikTok будуються з реплеїв).
- **Малий стан.** У JSON іде джерело землі + список вибухів, не сама маска.
- **Логіка = картинка.** Що бачить гравець, те й тверде.
- Ціль 60 FPS на середньому Android: вибух — це локальна зміна, без перерахунку всієї карти.

Не-цілі зараз: падіння відірваних шматків землі, різні типи ґрунту (камінь, що не руйнується),
будівлі, слизові ділянки (окрема механіка пізніше).

## Світ

- Розмір: **1600×720** одиниць світу (екран 1280×720 + по 160 з боків). 1 одиниця = 1 піксель
  маски = **2×2 пікселі арту** (`ART_SCALE` у `src/core/world.ts`).
- Камера: тримає поточного равлика, плавно доводить до снаряда; виходить за край світу на
  невеликий запас, щоб було видно падіння у воду.
- **Низ — вода (або сіль), смерть.** Рівень води задається картою. Пробив землю до дна — під
  тобою вода.
- **Боки відкриті.** Снаряд, що вилетів за межі світу, зникає без вибуху. Равлик, що з'їхав за
  край, падає у воду.
- Верху немає: снаряд може летіти вище екрана й повернутися.

## Підходи, що розглядали

| Підхід                                     | За                                                                              | Проти                                                  |
| ------------------------------------------ | ------------------------------------------------------------------------------- | ------------------------------------------------------ |
| **Попіксельна маска** (обрано)             | Точна відповідність арту, прості колізії (`isSolid(x, y)`), довільна форма карт | Пам'ять (1600×720), маску не можна класти в стан       |
| Карта висот (одна висота на колонку)       | Дуже мало даних                                                                 | Неможливі печери, нависи, тунелі — вибухи їх створюють |
| Груба сітка (клітинка 4–8 px)              | Менше пам'яті                                                                   | Сходинки на краях, розбіжність картинки й фізики       |
| Полігони (векторна земля, булеві операції) | Компактно, гладко                                                               | Складно, повільно, легко зламати детермінізм           |

## Модель у `src/core/terrain/`

- Маска: `Uint8Array` розміром `width × height`, 1 = земля, 0 = повітря. Байт на піксель, а не
  біт: простіше й швидше; ~1.15 МБ — прийнятно. Якщо пам'ять стане проблемою на телефонах,
  переходимо на бітсет без зміни API.
- Стан для JSON:

  ```ts
  type TerrainSource = { kind: 'hills'; seed: number } | { kind: 'map'; id: string };
  interface TerrainState {
    source: TerrainSource;
    craters: { x: number; y: number; r: number }[]; // у порядку вибухів
  }
  ```

  Маска — похідний кеш: `build(source)` → застосувати кратери по черзі.

- Операції (чисті, тестовані):
  - `isSolid(x, y)` — поза межами світу = повітря.
  - `carveCircle(cx, cy, r)` — піксель стирається, якщо його центр `(px+0.5, py+0.5)` в колі.
    Повертає змінений прямокутник (для оновлення текстури).
  - `surfaceY(x)` — перший твердий піксель зверху (для спавну й падіння).
  - `checksum()` — хеш маски (FNV-1a) для тестів детермінізму й, пізніше, перевірки розсинхрону.
- **Тільки детермінована арифметика.** У core без `Math.sin/cos/exp/pow` для генерації
  (їх точність не гарантована однаковою між рушіями JS). Лише `+ - * /`, `Math.floor`,
  `Math.sqrt`, `Math.imul` і сідований RNG.

## Джерела землі

### Пагорби з seed (MVP, першими)

Value-noise по колонках (кілька октав, RNG + плавна інтерполяція поліномом), згладження,
затиснення в межі. Гарантовано рівні майданчики для старту на ~20% і ~80% ширини. Ніяких печер:
їх створюють вибухи.

### Мальовані карти (одразу після пагорбів)

- Карта = `public/maps/<id>/terrain.png` (+ необов'язковий `back.png`, не твердий) + `map.json`.
  PNG растеризує `npm run maps` (resvg) із SVG у 2× (3200×1440).
- PNG — це **і арт, і маска**: піксель маски = блок 2×2 арту, земля, якщо середня альфа ≥ 128
  (ціла арифметика в core: сума ≥ 512). Арт у майбутньому генеруємо в Claude Design
  під конкретні запити; на MVP — 1–2 прості силуети-заглушки.
- JSON: `{ id, name, width, height, waterLevel, spawns: [{ x }] }`. Равлик з'являється над `x`
  і падає на поверхню.
- Декодування PNG — у шарі `game` (canvas → альфа-канал) → core отримує `Uint8Array` і будує
  маску. Сервер пізніше декодує той самий PNG бібліотекою — поріг альфи дає ідентичну маску.
- Перевірки при завантаженні: розмір PNG = розмір у JSON, є щонайменше 2 спавни.

## Рендер у `src/game/`

- **Роздільність:** бекбуфер канвасу = CSS-розмір × min(DPR, 2), не більше 3.2 Мп
  (`src/game/display.ts`); світ вписується зумом камери (висота 720 = висота екрана). HUD —
  окрема сцена з зумом = масштаб рендеру, тож його розміри в CSS-пікселях.
- Земля — арт у 2× (3200×1440), розбитий на тайли 256×256 одиниць світу (512×512 арту + 1 px
  «фартуха» з пікселями сусідів, щоб лінійна фільтрація не давала швів). Базовий арт малюється
  один раз із землі до вибухів (для карт — це PNG).
- Край, контур і кромка — з **поля відстані** (`src/game/terrain/edgeField.ts`): для кожного
  пікселя маски знакова відстань до межі земля/повітря (точна до 8 px, далі обрізана), злегка
  розмита [1 2 1]², щоб сходинки квадратних пікселів стали гладкою лінією. Арт читає її
  білінійно в 2×: покриття (згладжений край рівно на межі маски), контур `#2B1B12` 3.5 px,
  світла кромка свіжого зрізу (ґрунт ×1.25, 3 px), опік ≤ 35 % на 7 px. Розміри й кольори —
  `docs/art/tokens.json` → `terrain.outline`, `terrain.freshCut`, `burnRadius`, `burnOpacity`.
- «Свіжий зріз» = межа з повітрям, яке до вибухів було землею. На пагорбах контур іде по всьому
  силуету; на мальованих картах силуетний контур уже намальований в арті, тож рушій додає
  контур лише на свіжих зрізах.
- Декор — векторні спрайти поверх землі; у масці лише його тверда форма.
- Після кратера перераховується поле й перемальовується лише його прямокутник (+10 px), і на
  GPU заливаються тільки зачеплені тайли.
- Вода, небо, паралакс — окремі шари.
- Пам'ять землі: ~18 МБ GPU (тайли) + ~18 МБ CPU (базовий арт) + ~12 МБ полів і маски.

## Що лишається на реалізацію

Точні параметри шуму та висоти пагорбів, кольори-заглушки, як саме оновлювати текстуру в
Phaser 4 (CanvasTexture vs DynamicTexture — вибрати за швидкодією на телефоні).

## Стан реалізації (2026-11-02)

Зроблено: маска, кратери, пагорби з seed, стан + відновлення з JSON, рендер (базовий арт +
обпалені краї кратерів), пісочниця в `MatchScene` (клік — вибух, ←/→ — камера, R — нова карта).
Хеш маски для seed 1 у браузері збігається з тим, що закріплено в тестах під Node.

Заміри на десктопі: вибух + перемальовування — медіана 4.4 мс, максимум 16.6 мс; повне
завантаження карти — 69 мс. **Відоме вузьке місце:** `CanvasTexture.refresh()` щоразу заливає на
GPU всю текстуру 1600×720 (4.6 МБ). На слабкому Android це може коштувати кадр на вибух. Якщо
підтвердиться на телефоні — розбити землю на тайли (наприклад, 256×256) й оновлювати лише зачеплені.

Ще не зроблено: PNG-карти (`{ kind: 'map' }`), камера за равликом/снарядом.

## Оновлення 2026-11-02: земля у 2× з контуром

повністю прозорі/суцільні тайли.
