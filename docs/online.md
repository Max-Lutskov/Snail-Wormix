# Матч з другом за посиланням

Як це влаштовано: [`src/net/protocol.ts`](../src/net/protocol.ts) (повідомлення),
[`server/`](../server) (кімнати, сервер — джерело правди), [`src/game/net/Online.ts`](../src/game/net/Online.ts)
(клієнт).

- Сервер крутить матч із `src/core` 60 тіків на секунду, приймає ввід лише від гравця, чий хід,
  і розсилає обом ввід кожного тіку. Клієнти крокують той самий core з тим самим вводом.
- Щосекунди сервер шле контрольну суму стану; якщо клієнт розійшовся, він просить повний стан.
- У симуляції немає `sin/cos` (постріл передається вектором), бо вони можуть відрізнятися між
  рушіями JS. Онлайн грають на намальованій карті (`glade`), її маска однакова скрізь.
- Гравець, що перепідключився за тим самим посиланням, отримує поточний стан і грає далі.

## Локально

```sh
npm run server   # кімнати на :8787
npm run dev      # гра на :5173, /ws проксіюється на сервер
```

Відкрий http://localhost:5173, натисни «Грати з другом», відкрий посилання в іншій вкладці.

- **Телефон у тій самій Wi-Fi:** `npm run dev -- --host` і відкрий адресу з мережі, яку покаже Vite.
- **Друг деінде, без хостингу:** тунель на порт 5173, напр. `cloudflared tunnel --url http://localhost:5173`
  (або `ngrok http 5173`) — посилання з тунелю працює і для гри, і для `/ws`.

## Деплой (один процес)

Сервер сам роздає зібрану гру з `dist/`, тож деплоїться як один Node-застосунок:

```sh
npm ci
npm run build
PORT=8080 npm run server
```

На Fly.io / Render: команда збірки `npm ci && npm run build`, команда старту `npm run server`,
порт з `PORT`. Кімнати живуть у пам'яті одного процесу, тож потрібен один екземпляр
(без горизонтального масштабування), а перезапуск обриває поточні матчі.
